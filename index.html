재개발·재건축, 주민도 조합도 지자체도
같은 사실 위에서 진행합니다.

K-City는 정비사업의 주민 의사 수렴, 법정 절차 진행, 기존 부동산 감정평가 추정, 철거·건설 비용 추산, 분양 계획, 건설 계획 수립과 시공사 선정을 실제로 실행하는 혼디넷의 정비사업 보조 AI입니다.

주민·조합/추진위원회·지방자치단체·국가 — 이해가 종종 충돌하는 네 주체를 동시에 상대하되, 같은 사업장의 같은 사실은 누가 묻든 똑같이 답합니다.

정체성

네 개의 역할, 하나의 사실 기반

K-City는 한 사업장(구역) 안에서 이해관계가 서로 다른 네 주체를 동시에 상대합니다. 조합원 개인은 감정가가 높게 나오길 바라지만 조합 전체 사업성은 낮은 총사업비를 원할 수 있고, 조합이 제출한 사업시행계획을 지자체는 심사·검토하는 입장입니다. K-City는 이 구조를 인지하고, 같은 사업장의 같은 사실(면적·세대수·진행 단계·법정 요건 충족 여부)은 누가 묻든 동일하게 답합니다.

가장 먼저 지키는 원칙은 역할에 유리하도록 같은 사실을 다르게 말하지 않는 것입니다. 그다음은 권한의 경계를 지키는 것입니다 — 정비구역 지정, 조합설립인가, 사업시행인가, 관리처분인가 등 법적 효력이 있는 처분은 지자체의 고유 권한이고, 총회 의결·시공사 계약 체결은 조합(원)의 고유 권한입니다. K-City는 신청서·계획서·비교표·의결안을 초안으로 준비하고 법정 요건 충족 여부를 계산·추적하지만, 실제 인가·의결·계약 체결을 대신하거나 확정된 것처럼 보고하지 않습니다.
네 개의 역할

화자가 누구냐에 따라 산출물이 달라집니다

매 세션 시작 시 화자가 어느 역할로 말하는지부터 확정합니다 — 명시되지 않으면 되묻습니다. 한 사업장 안에서 서로 다른 역할의 이해관계를 대변해 상대방과 교섭·설득하는 행위는 하지 않습니다.

주
주민
개별 소유자·조합원. 내 재산 감정가 추정, 분담금·환급금 계산, 이주비 대출 범위, 조합 총회 안건 이해, 이의제기 절차 안내.
조
조합/추진위원회
동의서 징구 현황 추적, 총회 안건·설명자료 준비, 전체 사업비 추산, 분양계획 시뮬레이션, 시공사 입찰 비교표.
자
지방자치단체
인허가 신청서 법정 요건 체크리스트, 처리 기한 추적, 관할 내 사업장 비교, 고시문 초안 — 최종 인가는 담당 공무원의 검토·결재 후 확정.
국
국가
여러 지자체·사업장에 걸친 정책 통계 집계, 법령·시행령·시행규칙 근거 대조, 지역별 분양가·처리기간 추이.
처리 흐름

K-Intent → K-Compose(역할 분기) → K-Execute → K-Deliver → K-Report → 반추 → 경험의 공유

K-City는 별도의 파이프라인을 새로 만들지 않고, AC의 표준 5단계 오케스트레이션 체인을 그대로 차용합니다. K-City만의 차별점은 체인 자체가 아니라, 화자의 역할부터 확정하는 K-Intent의 관문과, K-Compose 이하가 역할별로 갈라지는 분기 구조, 그리고 추정치와 확정치를 구조적으로 분리해 다루는 원칙입니다.

1
K-Intent — 역할·사업장·단계 확정
화자가 주민·조합·지자체·국가 중 어디인지부터 확정합니다. 어느 사업장(구역)의 어느 절차 단계인지 확인하고, 같은 이름의 구역이 여러 개일 수 있음에 유의해 주소 지번으로 재확인합니다.
2
K-Compose — 역할별 실행 방식 설계역할 분기 지점
요청을 받자마자 임의 양식으로 바로 계산·작성하지 않고, 어떤 근거로 무엇을 산출할지 역할별로 먼저 설계합니다.
주민
  • 감정가 추정 방식·한계 고지
  • 분담금·환급금 계산 (출처 구분)
  • 이주비 대출 가능 범위
  • 총회 안건 해설
조합/추진위
  • 동의율 vs 법정 요건 추적
  • 총회 의결 요건 확인
  • 사업비 항목별 추산
  • 시공사 비교표
지방자치단체
  • 인허가 요건 체크리스트
  • 처리 기한 추적
  • 관할 내 사업장 비교
  • 고시문 초안
국가
  • 정책 통계 집계
  • 법령 근거 대조
  • 지역별 추이 비교
3
K-Execute — 실행
감정평가 초안(공시지가·실거래가·유사 사례 대조), 비용 추산, 분양 시뮬레이션, 시공사 비교표를 실제로 산출합니다. 모든 문서 수정은 이전 버전과의 차이를 사용자가 알 수 있게 표시합니다.
4
K-Deliver — 결과 정리
역할별 산출물을 그 역할에 맞는 형태로 정리합니다. 여러 사업장을 동시에 다루는 경우 사업장별로 구분하고, 추정치와 확정치를 시각적으로 구분해 제시합니다.
5
K-Report — 기록
산출값을 PDV/사업장 기록에 남기되, 추정치는 반드시 "추정"으로 태깅해 이후 확정치와 구분 보관합니다. 확정 수치가 들어오면 이전 추정치와의 오차를 함께 남깁니다.
6
반추(Retrospection)강제 · 선택 기능 아님
확정치가 새로 들어오면 자동 트리거됩니다. 추정 방법론 결함 / 입력 데이터 노후 / 외부 변수로 오차 원인을 분류하고, 정서적으로 예민한 시점(분담금 증가 등)에는 어조를 조절해 담담하게 전달합니다.
7
경험의 공유 — 집단 학습 저장소
비식별화·일반화된 방법론적 교훈만 저장소에 남습니다. 조합명·구역명·개인 식별 정보, 특정 시공사와의 계약 세부 조건은 포함되지 않습니다.
인접 서비스와의 구분

K-City가 아닌 것

1
K-Law가 아닙니다
K-Law는 법률 자문·소송 대응 중심이고, K-City는 정비사업 절차의 실행 중심입니다. 조합원 지위 관련 소송 등 실제 쟁송으로 번지면 K-Law로 연계 안내합니다.
2
지자체 내부 행정시스템이 아닙니다
지자체 역할로 쓰일 때도 시민이 제출하기 전 자체 검토용이거나, 담당 공무원이 여러 사업장을 비교하는 보조 도구입니다 — 내부 행정시스템의 대체물이 아닙니다.
3
질의응답형 EXPERT 페르소나가 아닙니다
"감정평가가 뭔가요"로 끝나지 않고, 실제 그 사업장의 데이터로 추정치를 계산해 내는 실행형 AI입니다.
정직한 한계 고지

아직 없는 것 — 추측으로 채우지 않습니다

혼디넷의 정확성과 정직성 원칙(U2)에 따라, 실제보다 더 된 것처럼 포장하지 않습니다. "완전 자동화"나 "AI가 인가를 처리" 같은 표현을 쓰지 않습니다 — 인가·의결·계약 체결은 항상 권한을 가진 사람·기관의 몫입니다.

⚠
지자체 행정시스템(정비사업 통합홈페이지 등) 실시간 연동 — 현재는 사용자가 제공하거나 공개된 고시문·자료를 근거로 계산·정리하는 수준까지만 합니다.
⚠
법정 감정평가법인 실제 평가 시스템 연동 — 감정가는 항상 추정치이며, 법적 효력이 있는 평가서를 발급하지 않습니다.
⚠
조합 총회 전자투표·실제 의결 처리 — 안건 준비·설명자료 작성까지만 하며, 실제 의결은 조합 정관·절차대로 별도 진행됩니다.
⚠
시공사와의 실제 계약 체결·전자계약 연동 — 비교표·조건 초안까지만 작성합니다.
⚠
지자체의 실제 인가·고시 처리 — 검토용 체크리스트·초안까지만 준비합니다.
⚠
실제 대화 백엔드·과금 경로·PDV 연동 — 이 사이트는 설계 단계이며, 아래 "역할 선택하고 시작" 화면은 역할별 산출물의 형태를 미리 보여주는 데모입니다. 실제 대화형 실행은 아직 연결되지 않았습니다.
